# Правила написания тестов

Читать перед тем, как добавлять или менять тесты. Цель: быстрый и надёжный набор, который ловит
реальные поломки (сейчас ~900 тестов, ~13 с локально, ~30 с на Windows в CI).

## Что тестировать
- Поведение, а не реализацию: вход → наблюдаемый результат (возвращаемое значение, ответ API,
  сообщение в WebSocket, запись в файл). Не проверять приватные поля и порядок внутренних вызовов.
- Ядро кода покрывать обязательно: счёт матов, настройки, серверное API, обновление, пресеты,
  распознавание (с подменёнными движками). Тривиальные геттеры и обёртки не тестировать.
- Каждая найденная ошибка получает регрессионный тест, который падает без исправления.
- Один тест — одна причина падения. Имя описывает ситуацию и ожидание
  (`test_final_adds_only_missing`), а не `test_1`.

## Скорость
- Тест не должен ждать реальное время. Нужна задержка — делайте её параметром и ставьте
  10–50 мс (`DELAY = 0.05` в `test_swear_tracker.py`, `RECV_TIMEOUT` в `test_obs_server.py`).
- `time.sleep` в тестах не использовать. Ждать условие: `wait_for(lambda: ...)` из `test_obs_link.py`.
- Медленный отказ соединения: на Windows подключение к закрытому порту отказывает ~2 с. Для
  закрытых портов FakeObs это уже обходит автоматическая фикстура `no_slow_refusals`
  (`conftest.py`). Для новых клиентов поступать так же: подменять отказ, а не ждать его.
- Сеть, микрофон, реальные модели, автозапуск, настоящие файлы проекта — только фейки
  (`fake_sd`, `run_key`, `models_dir`, `tmp_path`, FakeObs, FakeRecognizer). Тест не должен
  выходить в интернет и менять что-либо вне `tmp_path`.
- После добавления тестов смотреть `pytest --durations=10`: всё дольше ~0,5 с — повод ускорить.
- Не добавлять pytest-xdist: на 2-ядерных раннерах накладные расходы больше выигрыша.

## Надёжность
- Без случайности и зависимости от порядка: порт `0` вместо фиксированного, `tmp_path` вместо
  общих файлов, никакого состояния между тестами. Настройки и счётчики берутся из фикстур.
- Потоки и asyncio: тест сам останавливает всё, что запустил (`link.stop()`, `tracker.stop()`).
  Необработанное исключение в потоке роняет тест (`pytest.ini`), это нужно.
- Ожидания по времени с запасом: «не раньше» проверять паузой `DELAY * 3`, а не `DELAY * 1.01`.
- Платформенное поведение (Windows/macOS/Linux) проверять параметризацией и подменой
  `sys.platform`, а не условным пропуском: тесты должны идти на всех трёх ОС в CI.

## Структура
- Файл `tests/test_<модуль>.py` на модуль `app/<модуль>.py`. Общие фикстуры — в `conftest.py`,
  общие фейки (FakeObs и др.) импортируются из файла, где они определены.
- Похожие случаи — через `@pytest.mark.parametrize`, но не плодить десятки вариантов одного и
  того же пути: достаточно границ (пусто, одно, много, некорректное).
- Не дублировать проверки между файлами. Если поведение уже покрыто тестом уровнем ниже,
  тест API проверяет только проводку (статус, формат ответа).
- Текст ошибок, видимый пользователю, проверять по ключевой подстроке (`match="не отвечает"`),
  а не по полной фразе.

## Перед коммитом
```
.venv\Scripts\python.exe -m ruff check .
.venv\Scripts\python.exe -m pytest -q
```
Оба обязательны в CI. Ручные проверки в браузере — только перед финализацией и по согласованию.
